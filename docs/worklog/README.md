# 작업 일지 (worklog)

Claude Code 가 이 저장소(가상 MFC 현장)에서 한 작업의 "무엇을·왜·어떻게 검증했는지" 기록. 날짜별 1파일(`YYYY-MM-DD.md`), 항목은 시간순.
형식은 `../pmart-backend/docs/worklog/README.md` 를 따른다(시뮬레이터에 맞게 아래 규칙 5·6 추가).

## 규칙
1. **커밋 없이 일지만 쓰지 않고, 일지 없이 커밋하지 않는다.** 커밋할 때 같은 커밋에 일지 항목을 포함한다(커밋 SHA 는 푸시 직후 다음 항목 또는 같은 항목에 추기).
2. **실행한 검증만 적는다.** 실행하지 않은 테스트·빌드는 "미실행"으로 미결에 둔다.
3. 구조에 영향을 주는 결정은 일지에 적은 뒤 관련 문서(`docs/*.md`, `CLAUDE.md`)로 옮긴다. 일지는 결정 문서를 대체하지 않는다.
4. 비밀정보·개인정보·토큰은 적지 않는다.
5. **백엔드 확인 기록**: 작업 중 `../pmart-backend` 를 읽어 확인한 사실은 근거(파일·커밋·브랜치)와 함께 적는다. 백엔드는 읽기만 하며, 백엔드에 필요한 변경은 `docs/backend-requests.md` 에 적고 일지에는 "R-xx 추가/갱신"으로 남긴다.
6. 사용자가 넣은 원본 문서는 수정하지 않는다. 손댄 경우(사용자 요청) 그 범위를 적는다.

## 항목 형식
```markdown
## HH:MM 제목
- 요청: 사용자의 말(요약 또는 인용)
- 한 일: 변경한 파일·범위
- 백엔드 확인: 읽은 파일·커밋·브랜치와 확인한 사실 (없으면 생략)
- 결정: 선택과 근거 (대안이 있었으면 한 줄)
- 검증: 실행한 명령과 결과 (통과/실패/경고 수). 문서만 바꾼 경우 "문서만 — 시험 미실행"
- 미결: 남은 것, 가정, 확인 필요
- 커밋: SHA
```
